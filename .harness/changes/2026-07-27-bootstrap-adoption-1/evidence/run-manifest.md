# 扫描运行清单 — 门禁证据载体规则

本目录是本 Change Record 的**审计元数据**（按 harness-bootstrap Skill 的边界定义，
审计元数据不进入 `customization-record.md` 的目标资产表）。其中的
`carrier_sweep.py` 是本记录的**证据材料**，不是可复用的 Harness 组件，
因此**不在 `manifest.json` 中注册**——这一归属由设计方裁定。

## 被验证的对象

`.harness/rules/project.md` §2 的门禁证据载体规则：退出码独立必记；
stdout / stderr 分流独立捕获、分别按载体规则记录；载体分支 (a) / (b) / (c)
及 (b) 内部的「无非空行」「不可呈现码点」子分支。

`carrier_sweep.py` 中的 `carrier()` 是该规则的机械实现；扫描攻击的是这个实现，
因此扫描结论的效力以「实现忠实于规则文本」为前提。该忠实性由人工逐条对照，
是本证据链中唯一不可机械化的一环，如实声明。

## 算法

1. **定向用例**（52 个）：每个用例带**期望分支**，逐条比对实际分支。
   来源分五组：
   - A 组逐项对应 `docs/process/invariant-closure-design.md` §2.3 声明的对抗字节域
     （CRLF、无末尾换行、空文件、非 ASCII、C0/DEL/NEL/U+2028/U+2029、
     代理字符字节、字面转义与真实字符的碰撞）；
   - B 组覆盖规则不可呈现码点集的每个类别，**并包含集合外的边界邻居**
     （U+00A0、U+2027、U+202F、U+2065、U+206A），验证这些必须保持原文记录——
     只测集合内成员只能证明「不漏」，加测边界邻居才能证明「不误伤」；
   - C 组攻击「行」的字节级定义；
   - D 组攻击 UTF-8 可解码性边界（截断序列、overlong、代理、尾部坏字节）；
   - E 组回放本 Change Record 实际记录的七条门禁输出。
2. **随机模糊测试**：在全字节域上生成随机字节串，检查是否有输入逃出划分。

## 方法学声明（重要）

**随机模糊测试无法验证判据本身。** 它只能证明「没有输入落到划分之外」
（全函数性），不能证明「输入被放进了正确的分支」（判据正确性）。
上一轮交付只做了随机扫描并据此声称规则闭合，这是方法上的错误：
NEL / U+2028 / U+2029 这类反例即使被随机生成，也会被判为「有分支、无异常」
而顺利通过——它们的问题不是无分支可落，而是**落错了分支**。
因此定向用例（带期望值）是必需的，随机扫描只是补充。

## 复现命令

```text

```
