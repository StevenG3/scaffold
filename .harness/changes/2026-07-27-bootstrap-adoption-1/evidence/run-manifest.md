## 方法学声明（重要）

**抽样层能做什么、不能做什么。** 它对**每个被抽到的输入**做独立 oracle 核对——分支**与**载体值都比；
它**不能**证明的是**未被抽到的输入**。（早期版本的措辞「只能证明没有输入逃出划分、不能证明输入进入正确分支」
在加入逐样本 oracle 后已不成立，此处更正。）当年引入定向用例的理由仍然成立：
NEL / U+2028 / U+2029 这类反例即使被随机生成，也会被判为「有分支、无异常」而顺利通过——
它们的问题不是无分支可落，而是**落错了分支**。
因此定向用例（逐条携带期望分支）是必需的，随机扫描只是补充。

**只核对分支同样不够。** 载体规则的结果不止五个分支标签，还包括「记录了什么值」：
原文分支要逐字记录最后一个非空行，fallback 分支要记录正确的字节数与原始流 SHA-256，
空流要记录 `<empty>`。外部审阅用一个变异探针证明了这一缺口——把 `_digest()` 换成常量
`bytes=0 sha256=000...0` 后，47 行载体全错，而当时的扫描仍报 0 失败、digest 一字不变。

现在每个定向用例同时携带**期望载体值**，通过条件是分支与载体**双双**比中；
结果摘要也绑定了**实际载体值**。同一变异探针的当前结果：

```text
未变异：       failures=0   digest=00788ca3647b09be...
_digest 被打桩：failures=47  digest 改变
```

**但仅有定向用例的载体核对仍不足以支撑一个全称陈述。** 内部变异审阅构造了 M10：
只污染**不在这 69 个输入之内**的载体值。定向用例逐条仍然全绿，而摘要恰好绑定的
就是定向行，于是 digest 一字不变——「摘要能检出错误载体」这句话对定向域为真，
对定向域之外为假。

因此**随机域也获得了独立值 oracle**：`oracle_carrier()` 是同一规则的**第二次独立转写**，
它不调用 `carrier()` / `_digest()`，手工遍历字节而非使用 `split()`，
并直接由 `hashlib` 重建哈希串。`run_fuzz()` 对**每一个**随机输入同时比对分支与载体值，
两次转写只要在任意输入上分歧即计入失配并使运行见红。M10 的前后对比：

```text
整改前（无 oracle）： fuzz 不检查载体值    digest 不变      -> 绿
整改后：              fuzz_mismatches=170981  digest 改变  -> 红
                      （定向 failures 仍为 0，说明抓住 M10 的正是随机域 oracle）
```

**这一陈述随后又被外部审阅推翻，本轮如实收窄。** 20 万次固定随机运行是**抽样**，
不是长度 0–6 的全域穷举：该域共 282,578,800,148,737 个输入，本次固定序列只产生
**137,527 个唯一输入**。审阅方污染了一个未被抽到的输入（`b"\x00" * 6`），扫描依旧全绿。
因此「随机域上普遍成立」是假的，已撤回。

现在的陈述按层分述，每层只说它真正成立的范围：

| 层 | 覆盖 | 成立的陈述 |
| --- | --- | --- |
| 定向用例 | 69 个人工钉住的边界输入 | 每个输入的**分支与载体值**都与独立构造的期望**逐字节**相等 |
| **穷举扫描** | 长度 0–2 的**全部** 65,793 个输入 | **全称成立**：该子域内每个输入的分支与载体值都与独立 oracle 一致 |
| 抽样扫描 | 长度 0–6，固定 seed 的 200,000 次抽取、137,527 个唯一输入 | 每个**被抽到**的输入都经 oracle 比对；**未被抽到的输入不在证明范围内** |

全称承诺只在穷举层给出，因为那是唯一负担得起的地方；长度 3–6 不作全域承诺。

**期望载体独立构造**，不经被测代码：原文期望是手写的字面字符串；
哈希期望由**字面字节数** + 直接调用 `hashlib.sha256(raw).hexdigest()` 组成
（`hashlib` 不是被测对象，`_digest()` / `carrier()` 一次都没有参与构造期望）。
字面字节数会与真实输入长度比对，写错即在导入时报错。

**比较器本身也必须被验证。** 一个恒真的比较器会让全部用例通过、外观与正确实现无异。
生成表也带上自检结果：`--emit-markdown` 在输出头部写明该次运行的
比较器自检与 argv 自检通过数及随机域失配数——比较器一旦被污染，这些计数随之变化
（实测：恒真 → 1/5，恒假 → 4/5，忽略载体半边 → 2/5），因此该产物**自带有效性证据**，
而不是仅仅声称有效。

默认模式因此内置**比较器自检**：把已知正确的期望分别变异为「错误 SHA」「错误字节数」
「错误原文末行」「错误分支」，断言四者**均被拒绝**；再加一条**对照**——未变异的期望
必须**被接受**，否则一个恒假的比较器也能通过前四项。任一自检未达预期即非零退出。

## 认证层的单一来源（注册表驱动）

自验会话 A 与 B 各自独立复现了同一个 Critical：`certification_state()` 用**三个硬编码前缀**
分桶自检失败，而 `"certification:"` 不匹配其中任何一个，**被静默丢弃**——
认证自检失败时仍得到 `certified: YES`、exit 0，并覆盖正式表为 CERTIFIED。
同时 `CERT_LAYERS` 是一段**死代码**，从未被消费，因此「层集合」与「分桶集合」可以各自漂移。

整改：`CHECK_CLASSES` 是**唯一来源**，`CERT_LAYERS` 由它派生并被 `certification_state()`
实际消费（不一致时抛 `AssertionError`）；新增**兜底层**「未注册自检失败」——
任何前缀不在注册表中的失败标签一律使认证失败。**本机制实际保证的四条**（不多也不少）：

1. 已进入 `selftest_failures`、但前缀不在注册表的失败标签 → fail closed；
2. 已注册、但产出者缺失或执行数为 0 的类 → fail closed；
3. 写了符合命名约定（`selftest_*` / `_selftest_*`）却**未注册**的产出者 → **导入期断言失败**；
4. 渲染文本自相矛盾（FAIL 行 + CERTIFIED 标记等）→ 产物级守卫拒绝写入并 exit 1。

第 3 条是本轮新增：此前一个忘记注册的产出者根本不会被执行，也就没有失败标签可供兜底层捕获；
现在导入期扫描模块命名空间，凡符合产出者命名约定的可调用对象都必须出现在注册表中。
实测：在副本中定义未注册的 `selftest_forgotten` → 导入即 `AssertionError`，exit 1，不写任何文件。

实测两条反例（会话 A/B 的原始构造）：

```text
认证自检中有一项失败      -> default exit 1, --emit-markdown exit 1, PATH 被拒绝, 正式文件未变, 出现「does NOT certify」
注入未注册前缀的失败标签  -> default exit 1, --emit-markdown exit 1, PATH 被拒绝, 正式文件未变, 出现「does NOT certify」
```

## 认证裁决的结构（无共享布尔值）

`certification_state()` **只返回 layer 事实**，不返回裁决布尔值。每个出口都从**它自己渲染的那些行**
用 `all(ok)` 派生裁决，因此「CERTIFIED 表头压在 FAIL 行之上」在构造上不可能出现——
表头就是那张表算出来的。

外部审阅的原始变异（包住 `certification_state`、保留 layer 表、只把布尔值强制为 True）
**已无对象可污染**：不存在这样一个布尔值。实测该形状现在得到
`rc=1`、横幅为首行、无 CERTIFIED 标记、FAIL 行仍在表内。

此外还有一道**与派生逻辑无共享**的产物级写入守卫 `artifact_guard_violations()`：
它只读**渲染后的文本**，发现以下任一情形即拒绝写入并 exit 1：
「`**FAIL**` 行与 CERTIFIED 标记并存」「两个标记并存」「无标记」「未认证却非横幅开头」
「CERTIFIED 在场却有 `X/Y passed` 且 `X != Y`」「CERTIFIED 在场却有非零缺陷计数」。
渲染器与守卫**共用** `FAIL_CELL` / `PASS_CELL` 常量，并有一项自检实测「未认证渲染确实含 FAIL 令牌」——
消除守卫与渲染字面量各自漂移的隐患。

**残余风险（按层精确声明）**。上一版把残余笼统写成「伪造 layer 事实后渲染内部自洽」——
内部验证者证明**这个前提是错的**：伪造 layer 行确实不留 `**FAIL**` 单元，但**证言计数**
（`X/Y passed`）来自真实的检查结果，因此一张写着 `8/23 passed` 的 CERTIFIED 表并不自洽。
守卫已据此补上**证言完整性检查**：CERTIFIED 标记在场时，任一 `X/Y passed` 若 `X != Y` 即拒绝。

按层给出**当前**的可捕获性：

| 伪造对象 | 是否被捕获 | 依据 |
| --- | --- | --- |
| 定向层（把 directed layer 的 `ok` 改真） | **捕获** | 用例表逐行由真实比对渲染，失败行仍带 `**FAIL**` 单元 |
| 四类自检层（改 `ok` 为真） | **捕获** | 证言计数由真实检查结果生成，`X != Y` 触发完整性检查 |
| 未注册失败标签层 | **捕获** | 该层为真时残留标签会出现在层详情，且伴随自检失败计数 |
| 穷举层 / 抽样层（改 `ok` 为真） | **捕获**（本轮新增） | 守卫扫描层详情数字：CERTIFIED 在场时任何非零 `N mismatches` / `N failures` / `N undefined` / `N unrecognised` 即拒绝 |

**本轮再次收紧**：守卫现在还扫描层详情里的数字——CERTIFIED 在场时，任何
`N mismatches` / `N failures` / `N undefined` / `N unrecognised`（`N != 0`）即拒绝。
验证者的两个外科式伪造（穷举 7 mismatches、抽样 11 mismatches 挂在 CERTIFIED 下）实测均被拒。

因此上表最后一行由「未捕获」改为**捕获**。**当前真正剩下的残余只有一种**：
一次**把印出来的数字一并改掉**的整体伪造——即渲染文本从头到尾自洽地说谎。
那已经不是「守卫看不见矛盾」，而是**根本没有矛盾可看**，与「oracle 本身说谎」
（两次转写被同时改成同一个错误答案）属于同一类：任何只读产物的自洽性检查都无从发现，
必须靠独立复现来发现。

## 可信计算基披露（哪些东西仍被共享）

「独立」不是一个绝对属性，而是相对某个共享基线而言的。外部审阅证明了不披露的代价：
当期望与 oracle 都读取被测代码的 `CARRIER_EMPTY` 与 `UNRENDERABLE_SET` 时，
把 `CARRIER_EMPTY` 改成 `"<wrong>"`、或从集合里删掉一个未被定向用例覆盖的成员
（U+0001），被测实现已经违反规则，而全部检查仍然全绿。
因此本节精确列出**仍然共享**的东西，独立性声明只在此披露之外成立。

### 仍然共享（共因风险真实存在）

| 共享项 | 说明与残余风险 |
| --- | --- |
| Python 运行时与解释器 | 被测实现与两个检查侧跑在同一进程、同一 CPython 上。解释器层面的缺陷会同时影响双方。 |
| `hashlib.sha256` | 期望值与被测实现都用它。若它本身错误，双方同错且不可见。这是刻意接受的：它不是被测对象。 |
| `bytes.decode("utf-8")` 的严格性 | 分支 (c) 的判定双方都依赖同一个解码器。 |
| **两份不可呈现码点集的交叉断言** | `UNRENDERABLE_SET`（被测侧）与 `ORACLE_UNRENDERABLE_SET`（检查侧）是**两次独立转写**，导入时交叉断言逐元素相同：改动**任一侧**立即报错。但**同时改动两侧**是真正的共因，本方案不覆盖——这是已知且被接受的残余风险。 |
| 分支标签的语义 | 两份标签字面量内容相同（必须相同，否则比较失效）。若**同时**修改两侧且保持一致，分类语义可以整体改变而不被察觉——与码点集同属「双侧同改」类残余风险。 |
| 规则文本 → 实现的人工转写 | `carrier()` 与 `oracle_carrier()` 都是人按规则文本写出来的。两者写法刻意不同（手工遍历字节 vs `split()`、两份集合字面量），但**同一个人的同一处误解**可能同时进入两份转写。这是本证据链中最根本、也无法机械消除的一环。 |

### 已经不再共享（拆分记录）

| 项 | 拆分方式 |
| --- | --- |
| 空流载体常量 | 检查侧使用独立字面量 `EXPECTED_EMPTY_LITERAL`，**绝不**读取被测的 `CARRIER_EMPTY`；把后者改成 `"<wrong>"` 实测使默认模式 **exit 1**。 |
| 不可呈现码点集 | oracle 使用自己的第二份字面列表；单侧删除 U+0001 实测在导入时即 `AssertionError`，**exit 1**。 |
| 哈希载体串与原文期望 | 定向期望由字面字节数 + 直接 `hashlib` 调用构造，从不经 `_digest()` / `carrier()`。 |
| 分支标签常量 | 检查侧拥有自己的 `ORACLE_BRANCH_*` 字面量，定向期望也用它们；导入时**成对交叉断言**且**各自内部唯一性检查**。两项缺一不可：内部审阅的 S2 变异把两个标签改成同一个字符串，五分划分**静默塌缩成四分**而没有任何一对不相等——只做成对比较抓不到它。实测：S1（单侧改名）与 S2（标签碰撞）现在均在导入时 `AssertionError`，**exit 1**。 |

### 退出码语义（按模式，逐模式明确）

| 模式 | 退出码含义 |
| --- | --- |
| 默认（无参数） | **判定语义**：0 当且仅当全部 layer 事实为 PASS。layer 集合 `CERT_LAYERS` **由检查类注册表 `CHECK_CLASSES` 派生**（非手工维护）：定向层、四类自检（比较器 / 共因 / argv / 认证）、长度 0–2 穷举层、抽样层（含 undefined），外加**「未注册自检失败」兜底层**。任一层 FAIL 即 exit 1。 |
| `--baseline` | **报告模式**：退出码**不承载判定语义**，只表示运行本身完成（正常为 0）。该模式**预期见红**，若以失败数决定退出码，读者会把「基线如期见红」误读成「扫描失败」。 |
| `--emit-markdown`（认证通过时） | 输出正式表，退出 0。**该模式承载判定**（不是报告模式）。 |
| `--emit-markdown`（**认证失败时**） | **拒绝写入正式文件**并 exit 1（给出失败层清单）；无 PATH 时只向 stdout 打印带「不认证」横幅的诊断表，同样 exit 1。**报告能力与成功语义彻底分离**：认证失败的输出永远不会落到正式路径，也永远不会 exit 0。 |
| 未知参数 | 拒绝执行，stderr 打印错误与用法行，退出 **2**。 |
| **模式组合** | `--baseline` 与 `--emit-markdown` **互斥**，同时给出即拒绝执行、退出 **2**（两种顺序均拒绝）。此前二者可同时启用，会把 baseline 的 30 个失败与当前判据的 fuzz 计数混进同一个 digest，并按文档给出的重定向方式静默覆盖正式 `boundary-cases.md`。 |
| 重复同一 flag | 视为同一模式，接受。 |
| `--emit-markdown PATH`（认证通过时） | 接受；表由脚本**原子写入**（同目录临时文件 + `os.replace()`）。此前文档给出的是 shell 重定向，shell 一打开文件就截断，运行中途失败会在 Change Record 里留下零长度或半截的正式表。 |
| 无 `--emit-markdown` 的路径参数 / 多个路径 | 拒绝，退出 2。 |
| `-h` / `--help`（**单独出现**） | 用法打印到 **stdout**，退出 **0**。 |
| help × 任何其他 token | **拒绝，退出 2**。此前 `parse_args()` 见到 help 即提前返回，早于未知参数、互斥模式与路径校验，于是 `--help --bogus`、`--help --baseline --emit-markdown`、`-h stray.md` 全部 exit 0——新增的 help 入口把已声称闭合的参数域重新打开了。现在**先校验完整 argv，再选择模式**，且 help 必须是 argv 中的唯一 token（`-h --help` 也拒绝）。 |

参数域闭合：任一 argv 要么落入四个模式之一（default / baseline / emit / help），
要么被拒绝并退出 2。**该闭合只认证已交付的 argv 空间：新增任何 flag 都必须同时扩充 argv 自检，
否则旧的闭合结论对新空间不再成立**（本轮的 help 入口正是这样重新打开了上一轮宣布闭合的参数域）。默认模式内置的 **argv 自检（27 项）**逐条断言上述行为，
包括两种模式组合顺序、路径校验，以及 help × 未知参数 / × 各模式 / × 路径 / × 三元组合。

**模式矩阵（唯一权威）**：

| 模式 | 是否承载认证判定 | 退出码含义 |
| --- | --- | --- |
| 默认（无参数） | **是** | 0 = 全部 layer PASS；1 = 任一 layer FAIL |
| `--emit-markdown [PATH]` | **是**（自 R8 起） | 0 = 认证通过（有 PATH 时写入正式表）；1 = 认证失败（**拒绝**写 PATH；无 PATH 时输出带横幅的诊断表） |
| `--baseline` | 否，报告模式 | 恒 0（除非运行本身出错）；**预期见红**，永不写文件 |
| `-h` / `--help`、参数错误 | 否，协议状态 | help = 0；未知参数 / 互斥组合 / 非法路径 = 2 |

**每一格均已实测**（非法路径此前为假：不存在的目录与目录型目标会抛 `OSError` 栈回溯并 exit 1，
而认证正在 PASS——既推翻了矩阵，又把留给「判定失败」的 exit 1 花在了 IO 错误上）：

```text
default                                   exit 0
--baseline                                exit 0
--help                                    exit 0
--emit-markdown（无 PATH，认证通过）      exit 0
--emit-markdown PATH（认证通过）          exit 0，写入
--emit-markdown（认证失败）               exit 1，无 PATH 时输出横幅诊断表
--emit-markdown PATH（认证失败）          exit 1，拒绝写入
--help --bogus / -h stray.md              exit 2
--emit-markdown ""  /  "   "              exit 2
--emit-markdown /no-such-dir-4f2a/out.md  exit 2（父目录不存在）
--emit-markdown /tmp                      exit 2（目标是目录）
```

默认模式与 `--emit-markdown` 承载**同一个**认证判定；不存在「只有默认模式才算数」的说法。

对「定向用例逐条结果（**含输入字节、期望载体与实际载体**）+ 各分支命中数 + 失败/逃逸计数」排序后取 SHA-256：

```text
837bab632d8da7d73c66826c96dda4035b452b0a219be3f1e59a62e83ad2ed9c
```

摘要的**检测范围，精确陈述**：它绑定**定向行**的输入字节、期望载体与**实际载体**，
以及穷举层与抽样层的**汇总计数**。因此：定向行的实际载体变化、或任一层计数变化，摘要都会变化。
但它**不绑定未被执行输入的载体**——审阅方污染了 `b"\x00" * 6`（不在定向用例、不在长度 0–2 穷举、
