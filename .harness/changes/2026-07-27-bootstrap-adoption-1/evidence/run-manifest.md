## 被验证的对象

`.harness/rules/project.md` §2 的门禁证据载体规则：退出码独立必记；
stdout / stderr 分流独立捕获、分别按载体规则记录；载体分支 (a) / (b) / (c)
及 (b) 内部的「无非空行」「不可呈现码点」子分支。

`carrier_sweep.py` 中的 `carrier()` 是该规则的机械实现；扫描攻击的是这个实现，
因此扫描结论的效力以「实现忠实于规则文本」为前提。该忠实性由人工逐条对照，
是本证据链中唯一不可机械化的一环，如实声明。

## 方法学声明（重要）

**随机模糊测试无法验证判据本身。** 它只能证明「没有输入落到划分之外」（全函数性），
不能证明「输入被放进了正确的分支」（判据正确性）。
NEL / U+2028 / U+2029 这类反例即使被随机生成，也会被判为「有分支、无异常」而顺利通过——
它们的问题不是无分支可落，而是**落错了分支**。
因此定向用例（逐条携带期望分支）是必需的，随机扫描只是补充。

**只核对分支同样不够。** 载体规则的结果不止五个分支标签，还包括「记录了什么值」：
原文分支要逐字记录最后一个非空行，fallback 分支要记录正确的字节数与原始流 SHA-256，
空流要记录 `<empty>`。外部审阅用一个变异探针证明了这一缺口——把 `_digest()` 换成常量
`bytes=0 sha256=000...0` 后，47 行载体全错，而当时的扫描仍报 0 失败、digest 一字不变。

现在每个定向用例同时携带**期望载体值**，通过条件是分支与载体**双双**比中；
结果摘要也绑定了**实际载体值**。同一变异探针的当前结果：

```text
未变异：       failures=0   digest=179b7a01c134cf70...
_digest 被打桩：failures=47  digest=2c88f988cda012e0...  digest_unchanged=False
```

**期望载体独立构造**，不经被测代码：原文期望是手写的字面字符串；
哈希期望由**字面字节数** + 直接调用 `hashlib.sha256(raw).hexdigest()` 组成
（`hashlib` 不是被测对象，`_digest()` / `carrier()` 一次都没有参与构造期望）。
字面字节数会与真实输入长度比对，写错即在导入时报错。

**比较器本身也必须被验证。** 一个恒真的比较器会让全部用例通过、外观与正确实现无异。
默认模式因此内置**比较器自检**：把已知正确的期望分别变异为「错误 SHA」「错误字节数」
「错误原文末行」「错误分支」，断言四者**均被拒绝**；再加一条**对照**——未变异的期望
必须**被接受**，否则一个恒假的比较器也能通过前四项。任一自检未达预期即非零退出。

## 定向用例的来源

| 组 | 来源 |
| --- | --- |
| A | `docs/process/invariant-closure-design.md` §2.3 声明的对抗字节域，**逐项**对应 |
| B | 规则不可呈现码点集的**每个族**各取代表，**外加集合外的可见邻居**（见下） |
| C | 「行」的字节级定义 |
| D | UTF-8 可解码性边界 |
| E | 本 Change Record 实际记录的七条门禁输出回放 |

**关于 B 组的可见邻居**：邻居用例的作用是证明规则「不误伤」。因此邻居必须是**确实可见**
（或可见地占位）的**已分配**码点：本次采用 U+00A0、U+2010、U+2027、U+202F、U+3000。
**不使用未分配码点作邻居**——规则对补集不作任何断言，拿未分配码点当「应可原文记录」的
期望值等于替规则声称它并未声称的东西。

## 算法与参数

| 项 | 值 |
| --- | --- |
| 定向用例 | 69 个，逐条携带**期望分支与期望载体值**；两者都比中才算通过 |
| 随机域 | 全部 256 个字节值，长度 0–6（均匀） |
| 固定 seed | `SEED = 20260727`（写死在脚本常量中） |
| 迭代次数 | `ITERATIONS = 200000` |
| 依赖 | 仅标准库（`hashlib`、`random`、`sys`） |
| 确定性 | 无时钟、无环境、无文件输入；任何 Python 3.9+ 重跑结果一致 |
| 源码编码 | 纯 ASCII：不可呈现码点一律以 `\uXXXX` 转义出现，diff 可读 |
| 脚本 SHA-256 | `01f0c0b9891ba3114c6dd7d88e084c6f98363fdaa923ee2142c6c7303b186227` |

## 复现与再生成命令

```text
# 扫描（定向 + 随机），打印结果摘要
python3 .harness/changes/2026-07-27-bootstrap-adoption-1/evidence/carrier_sweep.py

# 再生成 boundary-cases.md（该文件由脚本生成，不得手工编辑）
python3 .harness/changes/2026-07-27-bootstrap-adoption-1/evidence/carrier_sweep.py \
    --emit-markdown > .harness/changes/2026-07-27-bootstrap-adoption-1/evidence/boundary-cases.md

# 红基线：以整改前的判据跑同一批定向用例，预期见红
python3 .harness/changes/2026-07-27-bootstrap-adoption-1/evidence/carrier_sweep.py --baseline
```

### 退出码语义（按模式，逐模式明确）

| 模式 | 退出码含义 |
| --- | --- |
| 默认（无参数） | **判定语义**：0 表示「定向用例零失败且无输入逃出划分」，1 表示存在规则缺陷。这是唯一以退出码承载判定的模式。 |
| `--baseline` | **报告模式**：退出码**不承载判定语义**，只表示运行本身完成（正常为 0）。该模式**预期见红**，若以失败数决定退出码，读者会把「基线如期见红」误读成「扫描失败」。 |
| `--emit-markdown` | **报告模式**：同上，退出码不承载判定语义，正常为 0。 |
| 未知参数 | 拒绝执行，stderr 打印错误与用法行，退出 **2**。 |
| **模式组合** | `--baseline` 与 `--emit-markdown` **互斥**，同时给出即拒绝执行、退出 **2**（两种顺序均拒绝）。此前二者可同时启用，会把 baseline 的 30 个失败与当前判据的 fuzz 计数混进同一个 digest，并按文档给出的重定向方式静默覆盖正式 `boundary-cases.md`。 |
| 重复同一 flag | 视为同一模式，接受。 |

参数域已闭合：任一 argv 要么落入三个模式之一，要么被拒绝并退出 2；
默认模式内置的 **argv 自检**逐条断言上述行为（含两种组合顺序）。

因此不要用 `--baseline` 或 `--emit-markdown` 的退出码判断规则是否成立；判定只看默认模式。

### 红基线（先见红，再见绿）

`--baseline` 以**整改前的判据**（只做字节级 C0/DEL 检查）跑同一批 69 个定向用例：

```text
directed cases: 69, failures: 30
```

30 个用例在旧判据下判错——全部是「严格可解码、不含 C0/DEL 字节，却不可呈现」的码点
（NEL、U+2028/U+2029、C1、软连字符、ALM、零宽字符、双向控制符、词连接符、
已弃用格式符、变体选择符、注释标记、BOM、标签字符）。
同一批用例在当前判据下全绿：这就是「回归测试先在被退回的判据上真实见红」的证据。

### 结果摘要（result digest）

对「定向用例逐条结果（**含输入字节、期望载体与实际载体**）+ 各分支命中数 + 失败/逃逸计数」排序后取 SHA-256：

```text
179b7a01c134cf70f68606c939e155390f0c21113811172a2f8d43e88fca63c6
```

摘要**绑定输入字节与实际载体值**，因此改动任一用例的输入、或让实现记录错误载体，摘要都会变化（上文变异探针即为实证）。
逐条用例表见 `boundary-cases.md`（由 `--emit-markdown` 生成，输入以完整 `repr` 呈现、不截断）。
